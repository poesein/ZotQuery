# ZotQuery 3.1.17

## 界面整理

- “研究工作台”统一更名为“研究台”。
- 设置按概览、模型与回答、检索与索引、外部模型接入、维护分类。
- 移除 Output Profile JSON 和默认台账格式选择；回答格式只由可选的用户 Markdown 模板控制。保留后台证据台账及高级笔记解析，不删除旧配置文件。
- 图片权限改为独立开关卡片，在设置与研究台即时同步。权限默认不变，不会因升级自动发送图片。
- 研究选项分开排列参数、检索复选项、说明和人工核验入口；人工审阅字段增加明确标签。
- 运行状态和“停止并保留”采用独立列，状态文字变长不再推动按钮。
- 右上角“ZotQuery 设置”使用实际注册的设置页 ID，定位插件设置而非通用设置。
- 预算控件仍在模型与回答区域；现有保存值、模式和思考强度不改写，自动策略按下述规则改进。

## 自动预算与传输保护

- 优先采用所选路由模型目录的输出上限，不把上下文容量当成输出上限。
- 未公布上限的 OpenAI 兼容路由：新研究不主动发送 max_tokens，使用服务端默认；这不代表无限，也不保证服务商默认就是最大值。已学习的续跑预算继续保留。
- 必须显式传预算的协议使用设置回退值；手动模式继续原样发送指定数值。
- 截断时按照服务商实际用量有限自适应；未完成的工具和正文不执行、不保存。
- 服务商明确拒绝预算并给出有效允许值时，自动校正最多两次。路由上限随同配置绑定的会话保留；当前请求剩余上下文额度不被记成永久模型上限。
- 请求体按实际 UTF-8 大小保护，阈值 32 MiB；自动模式对过大请求/HTTP 413 尝试一次会话恢复，并要求重新回读原文。
- 响应累计保护阈值 128 MiB，单个流事件保护阈值 16 Mi 字符；触发时终止接收、不重发超大响应、不把截断输出当作答案。这些是传输/内存保护，不是恢复已移除的本地 token 上限。
- 仍有总超时、取消、有限重试和结束标记校验；没有客户端策略能保证服务商默认值、限流和网络永不出错。

## 响应可靠性

- 兼容 OpenAI 风格正文文本块、单帧完整消息和 reasoning 字段；不再把未知对象转成字符串答案。
- 区分真正空消息、仅思考、格式不支持、拒答和截断。
- 已完整结束但仅有思考的 stop 响应，最多接续一次，保持预算和已完成工具结果；会产生额外 API 用量。连续空响应、格式异常、拒答和中断流不盲目重发。
- 失败时也记录该轮 token 用量、结束原因、字符数量与等待时间；不保存原始响应或思考正文。
- 台账排版失败不再阻止大模型答案保存。

## 数据与验证边界

- 不修改原始文献、笔记、PDF、个人模板、研究历史或已有 README。
- 离线回归涵盖响应解析、预算与续跑、台账隔离、持久化诊断、图片权限同步、设置页面定位及原有证据约束。
- 浏览器布局预览检查宽窄窗口与深色模式；其中 XUL 控件仅为预览适配。这不等于已在原生 Zotero 窗口中完成验收。
- 未运行付费服务商研究请求，不能凭旧日志确认第 19 轮空响应的服务端根因；本版修复已复现的解析及诊断缺口。
- 交付本地安装包与源码；未安装到用户 Zotero，也未发布 GitHub。
