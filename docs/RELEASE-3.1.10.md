# ZotQuery 3.1.10

本版本是通用研究工作流更新，不包含特定蛋白、问题的专用检索规则或预设答案。README 保持不变。

## 研究历史

- 工作台增加「研究历史」：按问题搜索、分页、打开旧会话、查看各次回答版本并续跑。
- API 回答自动写入本机 `zotquery-research.sqlite`；每次执行新增版本，不覆盖之前的回答。失败或重启中断的尝试也保留状态。
- 旧版已经存在的证据会话继续显示；旧版未自动保存的回答正文无法凭空恢复。之前手工导出的 Markdown 不受影响。
- 冷启动续跑从持久化事实、审阅记录和具体待办恢复，而不是把旧回答当成证据。完整模型对话仍仅存内存，重启不会恢复隐藏思考过程。
- 自动保存失败时保留当前可导出的正文并明确提示；切换会话前对未保存编辑进行确认。

## 通用证据判定

- 区分「值逐字出现在原文」和「原文完整支持事实槽」。每条新事实必须填写原文实际含义、对事实槽的支持理由和 full / partial / context / contradicts 支持关系。
- 旧事实不会删除或改写其值、来源；需重读后补充评估才能用于关闭精确事实槽，评估修订保留记录。
- 事实槽可限定实体、编号体系、单位、预期长度及所依赖的闭区间槽。单一同对象的序列与区间槽自动做长度一致性检查，防止局部片段冒充完整序列；多对象、多区间需显式声明关联。
- 局部或背景证据不与完整值机械地构成冲突，但不能代替完整答案。映射、观测、构建边界、片段及计算推导仍需明确区分。
- 原文上下文成功返回后才记录「已读」，并保存阅读快照。索引重建后不会静默用不同文本替换已经引用的原文。
- 新增通用待办工具，返回尚未读/审阅的位置、各事实槽缺口、冲突和笔记追溯游标；API 与 MCP 共用后端。

## 工作流和界面

- 修复证据列表始终只加载前 100 条的问题，增加前后分页和总位置编号。
- 修复 Survey 中的笔记因不在 sweep 首页而无法追溯的问题：根据 Zotero 的实际笔记—父条目关系补登记导航位置，再查同父 PDF；不虚构原文或阅读记录。
- 推广分页可以重试且不重复累计计数；失败页不会冒充完成。Survey 初始化失败时保留已创建的 PDF 会话，可在同一会话重试。
- API 工具调用核验 positionId / factId 所属会话，避免不同研究混用证据。
- 主工具栏从一开始就注册 ZotQuery 工作台图标，初始化期间暂不可点击。内核直接交给工作台注册，不再先创建旧搜索入口再删除替换；阅读器入口和搜索/索引 API 保留。

## 数据与分发边界

- 本版本新增表/列，不删除原有研究、笔记、向量缓存或用户模板；默认不提供个人 Markdown 输出模板。
- 新历史记录仅保存问题、回答、非敏感模型选项和核验摘要，不保存 API 密钥、服务地址、模板内容或模型隐藏思考文本。回答正文及问题本身可能含用户信息，是本地私有数据，不是发布资源。
- 安装包与源码包不包含研究数据库、研究报告、用户模板或本机配置。

## 验证边界与后续改进空间

离线测试涵盖真实 SQLite 语句、幂等迁移、历史版本、冷恢复、原文快照、支持关系/长度检查、工具协议、渲染/分页和工具栏注册顺序。另在真实旧数据库的只读备份上验证升级，原始数据库不作修改。

这些测试不等于真实 DeepSeek 答案质量验收，也不等于 Zotero 中重启后的视觉验收；本次没有自动安装、重启 Zotero、调用付费模型或发布 GitHub。

仍需注意：

- 语义判断仍由模型/人工完成，结构化评估不能保证模型推理必然正确；长度、单位等确定性检查是补充，不是自动科学裁判。
- 外部 MCP 客户端的系统提示、上下文管理和工具选择仍可能与内置代理不同，同一模型名不保证同样的研究表现。
- 本版本不新增联网序列数据库、结构解析或图像识读工具；需要从权威序列/结构数据计算的结果仍应明确标记推导，不能伪称 PDF 逐字事实。
- 超长研究的上下文压缩、原文按需重取及供应商上下文上限适配仍有改进空间；本版不静默截断原文来掩盖限制。
- 全局 Coverage Gate 仍要求完整覆盖；局部已支持内容可以有明确边界地陈述，不能宣称全量核验通过。
