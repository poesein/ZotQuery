# ZotQuery 3.1.5

修复“API 研究并生成”在证据核验未通过时用程序台账替代大模型回答的问题。

- 将研究取证与回答撰写分为两阶段。研究结束后，由所选 API 模型再撰写一次自然语言 Markdown 回答，材料来自实际工具返回原文及持久化证据；未核验草稿不作为事实输入。
- 模型提前停止而研究尚未完成时，在剩余轮数内最多两次提示继续读取、审阅、登记事实和终审核验。到达研究轮数上限仍进行回答撰写，因此通常比原流程多一次 API 请求。
- 核验未完成时生成明确标注限制的阶段性回答，要求说明已知证据和无法确认的部分；不会修改核验结果、自动填充事实或把候选数量当作阅读数量。
- 回答正文与证据台账分开。原“渲染”按钮改为“查看证据台账”；台账位于单独折叠面板，展开它不会覆盖回答或用户编辑。
- “复制回答”和“保存回答 .md”只使用回答编辑框；默认不附带全库候选表或机器 JSON。模型写作请求失败时明确报错，不回退为程序台账。
- 保留可选用户模板、原文跳转、思考强度、异步凭据保存、文件选择修复及小尺寸插件图标。不内置私人模板或研究记录。

验证范围为模拟 API/工具与界面逻辑、源码及发布包验证；尚未安装到运行中的 Zotero 执行真实 API 研究。文档不保证任一模型都能完成全部研究步骤或给出正确精确事实。
