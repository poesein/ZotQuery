# ZotQuery 3.1.14

修复“模型尚未完成回答，请再次点击续跑”的写作收尾缺口。不是单纯增加研究轮数，也没有降低用户选择的思考强度或放宽证据核验标准。

## 问题机制

旧实现的研究阶段结束后，最多再请求六次允许工具调用的写作/补查。模型若六次都选择补查，第六次工具结果虽然已经返回，程序却直接检查正文为空并抛错，没有让模型根据最后一次结果生成回答的机会。再次续跑又从研究阶段开始，可能重复消耗研究预算。

## 本版修改

- 保留原来的研究和最多六轮工具补查。若仍未生成正文，进入独立的正文收尾请求：保留最后一次工具结果、完整配对的工具对话和服务商思考元数据；明确禁用新的工具调用，要求模型直接输出面向用户的 Markdown 正文。
- 如果证据门禁尚未通过，正文只能是明确限定的阶段性回答：已有支持、未确定的部分和缺失证据。不会把台账、候选列表或确定性审计报告当成大模型答案；也不会仅因进入收尾就将状态改为核验通过。
- 写作中途或正文请求失败后，续跑接回写作/正文阶段，不重新开始一整轮规划。保存已完成补查轮数；手动预算和自动预算都支持阶段恢复。
- 重启或上下文恢复后，只有数据库导航、没有之前完整模型对话时，会给写作阶段有界的原文回读机会。未回读成功的草稿不采纳，最终仅允许明确标注无法确认的阶段性说明，并附加缺失原文回读的阻断状态。
- 正文收尾不因主动整理阈值而丢弃刚读取的原文。服务商真正拒绝上下文时则保留会话，续跑先回读再写作；截断正文、空响应和违规工具调用仍拒绝保存或执行。
- 兼容 3.1.13 已保存的写作阶段/轮数检查点。旧记录不覆盖，续跑生成新的运行及回答版本。预算学习和配置绑定沿用 3.1.13 的安全边界。
- 历史诊断增加“正文收尾”阶段和每次响应的工具调用数量，便于区分“已返回但一直在补查”和网络/输出截断故障。

## 协议依据

OpenAI 兼容/DeepSeek 请求在收尾使用 `tool_choice: "none"`；Anthropic 使用 `tool_choice: {type: "none"}`；Gemini 使用 `functionCallingConfig.mode: "NONE"`；Ollama 收尾不再提供工具定义。普通研究和补查仍允许工具调用，思考强度保持用户设置。

依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[Anthropic 工具选择与思考](https://platform.claude.com/docs/en/about-claude/models/extended-thinking-models)、[Gemini Function Calling](https://ai.google.dev/gemini-api/docs/function-calling)。兼容网关仍可能不完整遵循这些参数；如果其在收尾继续返回工具调用，本版明确报错并禁止执行，不静默改变协议或无限重试。

## 验证与使用

82 项离线测试及模型切换回归通过。新增覆盖：30 轮研究 + 6 轮补查后的正文机会、最终工具结果与模板/思考元数据保留、正文失败直接续跑、写作中途续跑、跨重启旧版写作检查点恢复、五类协议禁用工具、拒绝违规调用、正文截断重试、上下文恢复后回读、没有原文时不能标为核验通过。SQLite 测试使用真实数据库引擎并模拟 Zotero 原生行代理。

安装 3.1.14 后，从研究历史打开原会话，点击“大模型回答”续跑。无需删除研究数据、重建索引或仅为这条报错提高研究轮数。已有 3.1.13 写作检查点在模型配置保持匹配时可接回写作；重启后会先回读原文。

源码包/安装包进行逐文件哈希和隐私检查。README、个人模板、现有数据库和旧版发布文件保持不变；发布包不包含真实会话、诊断记录、密钥或个人研究内容。

没有调用付费 API，没有自动安装或重启 Zotero，没有发布 GitHub。离线模拟验证的是流程与持久化行为，不等于真实服务商的在线回答质量验收。
