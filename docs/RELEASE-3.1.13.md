# ZotQuery 3.1.13

本版修复 API 研究的预算、续跑、上下文整理和请求诊断流程，不针对某个研究问题增加专用规则。README、旧版发布包和用户原始模板不修改。

## 主要变化

- 自动模式在同一研究、相同模型配置下沿用上次已提高的预算，不再每次续跑都回到起始值。新版本运行产生的预算检查点可以跨 Zotero 重启恢复。成功用过的预算与当前尝试预算分别记录，后者不意味着服务商已确认支持。
- 预算记录通过不含地址或密钥的配置标识绑定。改变服务商、地址、模型、思考强度、起始预算、预算模式或温度会使旧预算失效；仅改变超时时间或研究轮数不会清除学习结果。手动模式严格使用手动预算，不自动增长。
- 服务商公布输出上限时仍优先采用该上限。未公布时从当前起点或同会话预算开始；普通输出耗尽后翻倍，服务商明确报告输出全部用于思考时改为四倍，避免反复尝试过小预算。每次研究最多增加预算重试两次；这些重试可能增加计费。不恢复固定本地 token 上限，也不把上下文容量当作输出上限。
- 基于服务商返回的实际输入用量整理过大的模型对话：软整理目标为公布上下文的 70% 与 180000 token 中较小者（最低 16384）。这是触发重新定位证据的策略，不是请求拒绝上限；缺少真实用量时不会用字符数代替 tokenizer 判定容量。每次研究最多主动整理两次，实际容量错误另允许一次恢复。
- 整理时重建完整、协议合法的对话，不剪断工具请求/结果对，不单独剥离签名或 DeepSeek 思考内容。数据库中的原文、阅读快照、事实、审阅和回答版本保持不变；模型须重新读取相关语段，空页不计为回读成功。单次原文读取结果仍不被偷偷截短。
- 请求发送前、响应返回后、工具执行完成后都保存进度。历史中可看到阶段、请求序号、实际预算、用量、HTTP 状态和耗时；异常结束或重启后不再只剩空诊断。
- 明确区分请求超时、认证/权限失败、限流/额度限制、服务端错误、参数拒绝、网络错误、上下文不足和空响应。不对这些传输错误盲目自动重发付费请求。每次等待前显示实际预算及超时设置。
- 工作台模型摘要显示已保存的预算起点与超时时间，便于核对设置是否真正生效；不恢复此前移除的长段说明。

## 升级与续跑

安装本版本后，在研究历史中打开原会话，点击“大模型回答”即可续跑，无需删除数据库或重建索引。已有模型配置、密钥、原文与回答不迁移覆盖。

3.1.12 及更早记录没有安全配置绑定，不能证明旧预算属于当前 API 地址；本版不会跨地址猜测继承其预算。第一次运行使用当前设置，之后可使用本版写入的检查点。旧版未记录的错误详情也无法追补。

最高思考强度仍由用户选择，不会在后台偷偷降低。插件不能保证服务商或兼容网关接受任意预算，也不能保证有限轮次内一定产出答案；截断响应始终不执行工具、不保存为完整答案。

## 验证范围

72 项离线测试与模型切换回归通过。包括真实 SQLite 与 Zotero 原生行代理模拟下的配置保存→请求→预算增加→故障→重启→续跑链路、配置变更隔离、大输入整理后的原文回读、HTTP 错误分类、检查点失败后的答案导出、隐私白名单、既有工具协议及证据门禁。

发布前验证安装包/源码包完整性、逐文件哈希一致、README 不变和隐私扫描。测试中的请求和研究数据均为合成数据，没有调用付费 API。未自动安装、重启 Zotero或发布 GitHub；离线测试不等于真实网关和研究答案质量的在线验收。
