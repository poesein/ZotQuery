# ZotQuery 3.1.9 — 内置 API 研究代理修复

本版为本地修复候选包，未自动发布到 GitHub，未改变线上自动更新。README 保持原样。升级使用原有插件 ID、凭据与索引，不附带用户模板或文献数据。

## 修复内容

- DeepSeek 思考开关与强度实际进入请求；关闭发送 disabled，低发送 low，中/高映射为 high，自动不覆盖服务端默认。完整保留并回传多轮 `reasoning_content`；同时保留 Anthropic thinking blocks 和 Gemini thought signatures。
- 研究与写作沿用完整对话、工具参数和原文结果，不再按 24 条/每条 12,000 字符/总 90,000 字符筛掉证据。写作可继续使用研究工具补查，补查后重新读取持久化核验状态。
- 执行并响应每一个模型工具调用，不再只执行前 8 个。非法/未授权调用返回匹配的错误结果，不因一项失败丢掉其余调用。
- 移除“两次继续提醒后提前结束”的限制；研究按用户配置轮数运行，之后最多 6 轮写作/补查。未闭合证据仍只能输出明确标注的阶段性回答，不能跳过 Evidence Gate。
- 同一次“大模型回答”点击内，先由模型规划，再自动建立会话。保留模型规划参数及用户阅读策略；禁止模型另开或操作其他 sessionId。同问题可续跑，不同问题/策略不会沿用旧界面会话。
- 最近 3 个研究对话仅保存在内存；失败或预算结束后，在同一工作台再次点击可继续。模型/服务/问题/策略变更不复用旧对话；Zotero 重启后不保留模型对话，但持久化证据台账仍保留。并发操作同一会话被阻止。
- `finish_reason=length` 等截断响应不再被当作完整回答。设置页增加单轮输出预算；预算需符合服务商/模型上限。
- “测试连接”改为两轮模拟工具调用与随机回执验证，覆盖工具结果和推理字段回传；不访问文献库，但会产生少量 API 用量。仍不等同于真实研究质量验收。

## 验证与限制

离线回归包含 DeepSeek 参数映射、完整推理字段回传、9 个并列工具调用、30 条长证据与超过 90,000 字符的单个结果、持续研究、写作补查、查询规划/会话隔离、网络错误续跑、输出截断、连接探针及另两种 provider 的协议字段保留，并保留原有渲染、凭据、模板、来源链接与证据门禁测试。

尚未进行真实付费 DeepSeek 同题 A/B、原生 Zotero 安装或 UI 验收。API 与外部 MCP 共用研究工具底层，但客户端提示词、实际模型、工具预算和上下文窗口仍可能不同，不能宣称所有模型上输出质量完全等价。

完整保留证据会增加请求上下文与费用。源工具自身的分页/截断边界仍存在，必须继续分页；若服务端上下文容量不足，显示请求错误并保留会话，不静默删证据。可缩小研究范围、新建任务或使用更大上下文的兼容模型。升级不会自动调用付费 API。

DeepSeek 适配依据：[官方思考模式与工具调用文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)。不同中转服务或旧模型对参数的支持可能不同，先在设置中完成新的工具连接测试。
