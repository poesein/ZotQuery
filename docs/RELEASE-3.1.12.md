# ZotQuery 3.1.12

修复 3.1.11 的本地上下文误拦截及大型台账恢复后仍过大的问题。README 不变，无个人模板、研究数据或密钥。

设置界面删除自动预算下方的长段说明文字，保留自动预算选项与原有行为。

同时删除思考强度下方的协议映射及兼容性说明文字，保留所有强度选项和后台参数映射。

删除研究轮数、模拟连接测试和最近会话保留的整段界面说明，不改变这些功能。

按用户确认解除 393216 本地 token 上限，并移除输入框原有固定最大值；自动预算仍遵守服务商公布的实际上限，每次研究最多增加预算重试 2 次。仅保留 JavaScript 安全整数校验，较大数字以字符串写入 Zotero 偏好，避免超出其整数存储范围。历史发布说明中的旧限制不适用于本版。

## 根因与修复

- 旧版以整个消息 JSON 的字符数乘以 2 预估输入 token，并据此在 HTTP 请求之前报「上下文空间不足」。该估计不是模型 tokenizer 的真实结果，英文、JSON 和思考元数据均可能造成严重高估。本版移除此本地硬拦截和基于字符数的输出预算压缩，不再把估计当作服务商确认。
- 旧版恢复上下文时，会把 coverage、evidenceSlots、nextActions 中重复的完整槽位评估重新放入对话；大型研究因此可能恢复后再次被本地拦截。
- 本版恢复只注入精简导航；大型冷恢复、写作状态、继续研究提示和台账类工具输出同样使用导航视图，明确标注 navigationOnly、truncated、列表总数与返回数。原文、事实正文和完整评估的省略明确可见，不能据此声称完整阅读。
- 导航保留会话、进度、部分槽位/事实/原文位置标识、待办及推广游标，要求通过工具定位并重读原文。冷启动只有导航的情况下也不接受未重新读取原文的直接答案。
- 不删数据库、不改覆盖门禁、不缩减研究范围；原文读取工具的内容不裁剪。只改变发给模型的大型状态注入，不改持久化研究记录、事实和阅读快照。
- 服务商真正返回上下文容量错误时，仍只进行有次数限制的恢复。真实模型/网关容量限制无法被插件绕过，截断响应仍不作为完整答案。

## 使用

安装 3.1.12 后重新打开工作台，从「研究历史」打开原会话，点击「大模型回答」续跑。原有模型、预算、密钥和研究记录继续使用；无需删除会话、重建索引或因这条本地错误而购买更大模型。

## 验证

62 项离线测试通过。新增覆盖：超过旧字符阈值但服务商接受的完整原文、错误目录容量不应本地阻断、多兆字节重复评估的冷恢复/恢复/写作有界导航、源数据不变、台账摘要显式省略、摘要恢复必须重读原文，以及解除本地 token 上限后仍遵守实际服务商上限和有限重试。
